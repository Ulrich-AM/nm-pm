# BS-004 - Sparse Persistent Blood Field Lifecycle

**Phase:** 2  
**Status:** Implemented  
**Milestone:** `blood-simulation-v0.3.0`  
**Date:** 2026-10-19

## Question

Can persistent blood state be stored only where blood exists while supporting accumulation, wetness, age, drying, and eventual freezing without updating dry regions forever?

## Field structure

Each surface owns a sparse set of 16 × 16 tiles.

Tiles are allocated only when an impact deposits blood into their covered region.

Each allocated cell stores:

- blood amount;
- wetness;
- age;
- local velocity U;
- local velocity V;
- frozen state.

Velocity channels are reserved for later phases. Phase 2 does not yet perform flow.

## Deposition

BS-003 morphology is sampled into the persistent field.

Repeated impacts add blood amount to existing cells rather than replacing the previous stain.

Wetness is refreshed by new material.

This provides the first implementation of:

```text
impact
  ↓
persistent amount
  ↓
overlap / accumulation
```

## Drying

Active wet cells update over time.

Wetness decays according to a controllable drying rate. Thicker cells dry somewhat more slowly.

When wetness falls below the freeze threshold:

- the cell is marked frozen;
- wetness becomes zero;
- local velocity is cleared;
- the cell no longer participates in lifecycle updates.

The visual stain remains persistent.

## Rendering

Field cells are rendered as world-space quads offset slightly from their supporting surface.

They participate in the native 3D depth buffer, so blood on a back wall can be occluded by an object or character in front of it.

Wet cells render brighter and redder.

Dry/frozen cells become darker.

## Sparse allocation

Untouched surfaces allocate no field tiles.

Memory therefore scales with affected surface regions rather than total room surface area.

## E2 lifecycle export

The Phase 2 lab can export:

```text
results/phase2/E2_field_lifecycle.csv
```

The sweep records field state over a simulated 60-second lifecycle, including:

- wet cells;
- frozen cells;
- active tile count;
- total blood amount;
- estimated allocated field memory.

## Success condition

The field is useful if it can:

- accumulate repeated deposits;
- preserve static state;
- stop updating dry cells;
- avoid allocating dense storage across untouched surfaces;
- retain the same world/surface coordinate contract established in Phase 0.

## Known limitations

- amount does not yet spread between cells;
- wetness affects appearance and lifecycle only;
- velocity channels are reserved but inactive;
- there are no drips or puddles;
- frozen regions are logically inactive but not yet baked into a separate texture object.
