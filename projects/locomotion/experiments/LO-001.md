# LO-001 - Static Anatomy, Coordinates, and Contact Foundation

**Phase:** 0  
**Status:** Implemented  
**Milestone:** `locomotion-v0.1.0`  
**Date:** 2026-10-20

## Question

Can the locomotion study establish a renderer-independent anatomical rig, coordinate convention, hierarchy, joint-range model, and foot-contact representation that later gait experiments can depend on without inheriting assumptions from one FBX rig or rendering system?

## Coordinate convention

```text
+X = subject right
+Y = subject forward
+Z = up
```

The basis is right-handed:

```text
X cross Y = Z
```

Camera and raylib axes are presentation-only conversions.

## Reference subject

LO-001 uses one deterministic neutral reference body with fixed proportions.

The body contains major torso, arm, and leg joints plus explicit heel, toe-base, and toe-tip markers.

The reference subject is a controlled baseline, not a claim that one set of dimensions represents all people.

## Range-of-motion model

Enabled joint axes contain a comfortable interval nested inside an outer interval.

The distinction exists because maximum clinical ROM should not become the normal locomotion target.

The Phase 0 ranges are research guardrails. Sagittal limits are informed by healthy-adult ROM literature; some frontal/transverse limits are provisional and must be revisited before later experiments depend heavily on them.

## Foot representation

Each foot contains:

- ankle;
- heel marker;
- forefoot / toe-base marker;
- toe-tip marker;
- a rectangular support patch derived from heel, forefoot, and foot width.

This prevents later phases from reducing the foot to one IK target and leaves room for heel strike, flat support, heel rise, and toe-off.

## Y Bot boundary

An untextured Y Bot is considered a suitable future visual test subject.

LO-001 deliberately does not import it yet. The mathematical locomotion contract must remain valid even when no FBX asset is present.

A later adapter may map the locomotion joints and body pose to Y Bot or another humanoid skeleton.

## Native harness

The Phase 0 native application provides:

- large orthographic anatomy viewport;
- three-quarter, front, side, and rear-three-quarter views;
- coordinate axes;
- foot support patches;
- optional joint labels;
- compact ROM display;
- live validation summary.

The UI follows Sprite Projection and Blood Simulation rather than introducing a new visual system.

## Automated checks

The native test executable verifies:

1. right-handed basis;
2. reference-body validation;
3. centered pelvis;
4. mirrored hips;
5. mirrored knees;
6. grounded heel and forefoot markers;
7. nonzero foot support width;
8. neutral pose inside enabled outer ranges.

`validateReferenceBody()` also checks finite joints, hierarchy indices, paired leg lengths, nested ROM ranges, grounded contact markers, and heel-to-toe ordering.

## Success condition

LO-001 succeeds when later experiments can consume the body without needing to reinterpret axes, replace foot geometry, derive symmetry from a model file, or use renderer-specific joint definitions.

## Intentional omissions

LO-001 does not implement:

- walking;
- gait phase;
- IK;
- COM or segment masses;
- support polygons;
- active balance;
- physics actuation;
- ragdoll behavior;
- terrain queries;
- FBX import.

These omissions are the point of the experiment, not missing Phase 0 features.
